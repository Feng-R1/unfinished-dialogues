## 本次更新：殿堂回响声音体验

- 已实现本机 Web Audio 原创音景：缓慢起伏的低频与泛音、合成房间混响、少量钟磬回响。无音频素材下载、额外依赖、麦克风访问或音频服务费用。
- 总开关默认关闭；主动点击才创建并恢复 AudioContext。分别控制空间氛围、交互回响，并提供 0–100 音量和试听。只对开启问题、进入/切换先贤及开场触发声音，流式文字与打字不触发。
- 浏览器实际测到 `AudioContext.state=running` 和非零音频输出。以设置面板内连接真实输出链的 AnalyserNode 测得：首页 35% 音量 RMS 抽样约 0.031356，进入已有庄子深聊后约 0.006863，场景状态为 chat。该抽查验证有声音及场景减弱，不等同于音质评分或响度校准。
- 将音量调至 0，实际输出为 0；关闭氛围后能单独试听交互音；关闭交互音后试听不可用。关闭声音总开关后，状态变为 suspended、输出为 0。
- 刷新后声音总开关仍关闭，测试设置的 20% 音量和两项关闭偏好均保留；验收后恢复 35% 及两项启用偏好。
- 正式版开场中点击“开启声音”，状态切换成功；可跳过返回首页继续播放。另在仅保留交互音时快速跳过有声开场，随后测得输出回到 0。代码取消尚未播放的开场声音，并淡出已响的尾音。
- 开场两个控件的 Tab / Shift+Tab 循环、Esc 退出已检查；跳过后键盘焦点回到“重映开场”。
- 手机 390×844 设置面板与 320 像素窄屏常驻声音按钮实际查看，无横向溢出。正式版浏览器未捕获 console error。
- 最终 `npm run build` 退出码 0，包含 TypeScript 检查；现有 14 项本机模拟测试通过，0 失败。本轮不新增真实模型调用。生产服务仍为 `127.0.0.1:3000`。

实现了页面 visibilitychange/pagehide 暂停、回前台恢复、组件卸载关闭音频上下文。当前内嵌浏览器创建的不同标签均报告 visible，未据此声称完成系统后台切换实测；设备扬声器的实际听感、跨浏览器行为及长时间播放仍待试听。验证依据是实际音频信号与控制状态，未将截图或按钮变化当作人工听测。

### 真实模型

- 从 [DeepSeek 官方入门文档](https://api-docs.deepseek.com/)与[模型说明](https://api-docs.deepseek.com/quick_start/pricing)核对：`deepseek-flash` 当前由 DeepSeek-V4.1-Flash-1017 提供，官方 base URL 为 `https://api.deepseek.com`。
- 使用用户提供的密钥请求官方 `/models`，鉴权成功，返回 `deepseek-flash` 与 `deepseek-v4-pro`。密钥只写入本机 `.env.local`；该文件符合 `.gitignore` 中 `.env*` 规则，未将其内容写入文档、测试或客户端。
- 从浏览器提交合成问题“我想换一个方向，但害怕失败，也害怕辜负家人的期待。我该如何想清楚？”，庄子、加缪、爱比克泰德三份真实回复均完成。
- 在庄子分支连续追问两轮，回复针对新的内容并延续前文。刷新后恢复原始问题、首轮回应及两轮追问；页面无回复错误提示。
- 三次首轮和两次追问的开发服务请求日志耗时约 1.3–2.5 秒。仅代表这五个请求的完整请求时间，不是首字延迟或正式性能评测。
- 最终生产服务另做接口抽查：HTTP 200、NDJSON 的 `done.mode` 为 `live`、错误事件 0；本次返回 213 字、三段、12 字标题。第一次 PowerShell 抽查未将字节数组正确解码，未作为通过依据；改用 Node.js 的 UTF-8 文本解析后确认上述结果。
- 根据[官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode)，该服务默认启用思考模式。本应用显式设置 `thinking.type=disabled`，直接流式展示回答，避免隐藏推理消耗首轮短输出预算。
- 模型有一次省略短标题，实际触发原页面将整段正文显示为标题的问题。已增加显示处理：缺少合适标题时采用人物的思想切入点作标题，正文完整保留；新增回归检查，并在实际页面确认旧回复显示恢复正常。
